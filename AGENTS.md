# AGENTS.md

This file is the **authoritative development guide** for AI coding agents (Claude Code, Codex, Cursor, etc.) and human contributors working in the Castor repository. The AGENTS.md files in subdirectories provide detailed references for each app:

- [apps/api/AGENTS.md](apps/api/AGENTS.md) — Go backend: layering, patterns, adding modules, RBAC/menus, migrations, testing
- [apps/web/AGENTS.md](apps/web/AGENTS.md) — Next.js frontend: data layer, pages, tables/forms, permissions, i18n, testing
- [deploy/README.md](deploy/README.md) — image builds, Compose / Kubernetes deployment, backup and restore

When docs conflict with code, **code and tests win**; fix the docs in the same change.

## 2. Working principles

1. **Design straight to the target**: the project is in development; keep no compatibility layers, deprecated fields, or half-finished compromises.
2. **Develop on `main`**, no branches; commit only when the user asks.
3. **Complete end to end**: land every layer a feature touches (migration, domain, service, interface, RBAC resources, menus, frontend, i18n, tests, docs) in the same change.
4. **Four-language i18n**: all user-visible text goes into translation files, kept in sync across `zh / en / ja / ko`; no hardcoding. Operator-editable data that cannot be pre-seeded into translation files (menu titles, dictionary type names and dictionary item labels) is carried in four-language fields (backend `shared.I18nText`, frontend `I18nText` in `lib/i18n-text.ts`); all four languages are required.
5. **Read before writing**: before changing anything, read existing implementations of the same kind and follow their patterns; reference modules are listed in the subdirectory AGENTS.md files.
6. **Never hand-edit generated files**: `apps/api/cmd/castor/wire_gen.go`, `apps/api/openapi.json` (regenerated with `go test ./internal/interfaces/api -run TestOpenAPISpecIsUpToDate -update-openapi`), `apps/web/.next/`, and lockfiles are produced only by tools.
7. **Tests travel with changes**: when fixing a bug, first write a test that reproduces it; add unit tests for new logic.
8. **Never weaken security invariants** (see section 6); never loosen validation to make tests pass.
9. **Windows, macOS and Linux are all first-class**: development, verification and deployment tooling is Python (stdlib) that starts tools with argument lists — no shell scripts, `sh -c`, or Unix-only tools such as `openssl`/`id`/`gzip` (the Git hooks are the one exception: Git runs them with its own `sh`). Build paths with `pathlib`/`filepath`/`path.join`, never assume `/` separators, `:` in PATH or POSIX mode bits in tests, and keep files LF (enforced by `.gitattributes`). Paths sent to Linux containers or remote hosts stay POSIX.

## 3. Verification: definition of done

```bash
python3 scripts/check.py            # everything (api + web + scripts)
python3 scripts/check.py api        # gofmt, go vet, go test -race
python3 scripts/check.py web        # oxfmt, oxlint, tsc, vitest, next build
python3 scripts/check.py scripts    # unit tests for deploy/dev scripts
python3 scripts/check.py vuln       # dependency vulnerability scan (govulncheck + bun audit)
```

On Windows use `py -3` instead of `python3`. `-race` needs cgo; without a C compiler (`go env CGO_ENABLED` is `0`, the usual case on Windows) `check.py api` runs the tests without it and says so.

`vuln` is not part of `all`: it needs network access to fetch the vulnerability database and takes a while; run it separately before releases or periodically. It fails on Go vulnerabilities our code actually calls and on any `bun audit` finding. A called vulnerability without an upstream fix may be accepted in `ACCEPTED_GO_VULNS` in `scripts/check.py`, with the reason and the hardening test; the entry stops counting as soon as a fixed version exists, and the scan then asks for the upgrade.

Before a change is done, the affected targets must pass. The tests below are the repository's "guardrails"; a failure means a layer was missed — **fix the omission, not the test**:

## 4. Local environment

```bash
python3 scripts/dev.py prepare   # start PostgreSQL/Redis/RustFS, generate config, init-db
python3 scripts/dev.py stop      # stop infrastructure (keeps data volumes)
```

- Alternatively press F5 in VS Code (configuration `Castor`) to start the Go and Next.js debuggers together.
- Python 3.11+ is required; on Windows the VS Code tasks use `py -3`, so install Python with the launcher and replace `python3` with `py -3` in manual commands too. The script checks the Python version before creating infrastructure.
- Generated files live in `.local/dev/` (ignored): `settings.json` (ports, `admin_password`), `api.config.toml`, `debug.env`.
- `prepare` also generates `.claude/launch.json` from the selected ports (the Claude Code Browser pane launch config, ignored). Do not write it by hand: `dev.py` picks different ports on conflict, and a hardcoded copy makes the preview open a blank page without any error.
- Default admin is `system`; API defaults to `http://127.0.0.1:1234`, Web to `http://127.0.0.1:3000`; ports are reassigned automatically on conflict, and `settings.json` is authoritative.
- Without F5: run `python3 scripts/dev.py run api` and `python3 scripts/dev.py run web` in two terminals. They load `debug.env` (the actual ports and connection settings) and drop any `CASTOR_*` inherited from the terminal; the Browser pane's generated `launch.json` uses the same commands.

## 5. Adding a business module end to end

The following is the cross-stack checklist; details and code templates are in the subdirectory AGENTS.md files. For paginated CRUD, use backend `audit_log` and frontend `resources` as references.

**Backend (apps/api)**
1. Domain: `internal/domain/{name}/entity.go`, `repository.go` (pure Go, no GORM).
2. Persistence: the Model in `persistence/models/` (GORM tags, `ToEntity`/`FromEntity`) + `persistence/{name}_repository.go` (`PaginatedQuery`, `translateError`).
3. Migration: append a new version in `internal/infrastructure/database/migration.go` and increment `CurrentSchemaVersion`; never modify released versions.
4. Application layer: `application/dto/{name}.go`, `application/service/{name}.go`, sentinel errors in `application/apperror/errors.go`.
5. Interface layer: `interfaces/api/handler/{name}.go`; register it in `router.go` under `AdminHandlers`/`UserHandlers`; the error-code chain has 5 places (`apperror` → `messages.go` → `errcode.go` → `handle_error.go` → i18n toml), see "Error-code chain" in the api AGENTS.md.
5a. API docs: add an entry per route to `apiOperations` in `interfaces/api/openapi_catalog.go` (request body type, response `data` type or `list(item, filterModel)`), then regenerate `apps/api/openapi.json` (see principle 6).
6. RBAC: register every `/api/v1/admin/*` route in `DefaultResources` in `internal/domain/permission/entity.go` (path = Gin route template, same method).
7. Menus: `bootstrap/menu_tree.go` has **four** parallel registration points (`systemMenuTree`, `menuModules`, `menuPageResources`, `defaultActionTitles`); missing any one raises no error and only makes menu entries disappear or duplicate; `menu_test.go` guards this; details in section 4 of the api AGENTS.md. `init-db` reconciliation only adds, never modifies; rerun it on an existing database to get the entries.
8. Dictionaries: use Go constants for enum field values and leave display to dictionaries — register in `DefaultDictTypes` / `DefaultDictItems` (four-language labels, colors, icons), and add the type code to `DICT_TYPES` in frontend `src/lib/dict.ts`; no migration needed. See "Dictionaries" in the api AGENTS.md.
9. File fields: inject `service.AssetReferencer`; entities store only the asset `objectKey`; never write to object storage yourself or delete assets directly. See "Files in business modules" in the api AGENTS.md (reference: avatars and notification attachments); on the frontend use `<FormAssetField>` / `<FormAssetListField>`.
10. DI: add the Provider in `cmd/castor/wire.go`, then run `cd apps/api/cmd/castor && wire`.

**Frontend (apps/web)**
11. Data layer: `src/features/{name}/api/{types,service,queries,mutations}.ts` + `service.test.ts`.
12. Components: `schemas/{name}.ts` (zod), `components/{name}-listing.tsx`, `{name}-form-sheet.tsx`, `{name}-table/{index,columns,cell-action}.tsx`; render enum columns with `<DictBadge>` and provide filter options with `useDict().options()`; do not write translation keys or color `switch` statements for enum values.
13. Page: `src/app/dashboard/{name}/page.tsx` (`PageContainer` + `serverHasPermission`); add new URL filter parameters to `src/lib/searchparams.ts`.
14. i18n: in `messages/{zh,en,ja,ko}.json`, `nav.{name}`, `dashboard.{name}Description`, the module namespace, `seedResources.*`, `resources.modules.{module}`; in backend `configs/i18n/*.toml`, `seedResources.*`.

**Wrap-up**
15. `scripts/check.py` passes in full; update affected AGENTS.md files.

## 6. Security invariants

| Rule | Implemented in |
|------|----------|
| Client `order` must never go directly into `.Order()`; only whitelisted columns + `asc/desc` are allowed | `internal/pkg/query/order.go`, handler `ValidateOrderParam`, repo `PaginatedQuery` |
| Filter/sort fields exclude `json:"-"` and password, secret, and token columns | `query.IsSensitiveColumn`, `handler/common.go` |
| All `/admin/*` routes pass through JWT + CSRF + RBAC middleware and are registered as resources | `router.go`, `middleware/admin.go`, `router_rbac_test.go` |
| Public routes must be rate limited | `middleware.RemoteIpPathRateLimit` |
| Unauthenticated `/api/v1/dictionaries` returns only `IsPublic` dictionary types; non-public and nonexistent both return 404; dictionary types are non-public by default | `GetAllPublicDicts` / `GetPublicDictItems` in `service/dictionary.go` |
| The `value` of system dictionary items (seeds) cannot be modified or deleted — it is the only link key to enum constants in code | `PutItem` / `DeleteItem` in `service/dictionary.go`, `database.SeedDictionary` |
| Assets referenced by business records cannot be deleted, taken offline, or made non-public (`ErrAssetInUse`); business code only removes its own references and never deletes assets directly | `ensureUnreferenced` in `service/asset.go`, `AssetReferencer` |
| Unauthenticated asset downloads allow only `IsPublic` + `ACTIVE` + non-high-risk types; everything else returns 404; all upload entry points share the same validation pipeline (content sniffing, field policies may only tighten the global policy, high-risk types forced private) | `PrepareDownload` / `store` in `service/asset.go`, `narrowedBy` in `service/policy.go` |
| When a business module downloads a private file it must verify both "the record is visible to the current user" and "the file is actually attached to that record"; any failure returns an empty 404; responses to end users expose only the attachment view (the display name set by the referencing record), never the asset's name, uploader, etc. | `AssetReferencer.PrepareAttachedDownload`, `DownloadAttachment` in `handler/notification.go`, `dto.AssetAttachmentResp` |
| Revoke sessions on password change/reset and user disable | `RBACService.RevokeUserSessions` |
| TOTP: a correct first factor on a two-factor account only yields a 5-minute, 5-attempt, single-use challenge (`errorCode` 2012), never a session; an accepted code advances the user's last used time step atomically, so a code (or an earlier one) is never accepted twice; recovery codes are single-use and stored hashed; TOTP secrets are encrypted with `Security.DataEncryptionKey`; OIDC sign-ins of a two-factor account go through the same challenge | `service/mfa.go`, `LoginWithTOTP` / Authenticator in `middleware/auth.go`, `handler/sso.go` |
| OIDC: authorization code flow with PKCE (S256), single-use `state` (Redis `GETDEL`) and `nonce`; ID tokens are verified (signature via JWKS, issuer, audience, expiry); accounts are matched only by (provider, subject), **never linked by email**; unknown subjects are registered only when the provider allows it, and only a provider-verified, unused email is copied; redirect targets must be site-relative; the last sign-in method of a password-less account cannot be unlinked; client secrets are encrypted and never returned | `service/sso.go`, `handler/sso.go` |
| Notification stream: only the signed-in user's events, at most 5 concurrent streams per user; the stream ends when the access token expires and when a heartbeat finds the session revoked; it is the only response that lifts the server `WriteTimeout` | `handler/notification_stream.go`, `service/notification_stream.go` |
| Notification emails go only to enabled users with a verified email who have not muted them (re-checked at send time); content is HTML-escaped, subjects cannot inject headers, links are site-relative or http(s) only | `service/notification_email.go`, `persistence/notification_email_repository.go` |
| Sensitive values stored in the database (TOTP secrets, OIDC client secrets) are AES-256-GCM encrypted with a per-purpose key derived (HKDF) from `Security.DataEncryptionKey`, which is required outside development and must be backed up with the database | `pkg/secretbox`, `config/load.go` |
| Managing another user (password, status, expiry, deletion, forced sign-out, removing roles) requires holding every permission and at least the data scope that user holds; a missing caller identity is rejected | `RBACService.EnsureCanManageUser`, `userService.ensureCanManage`, `sessionService.Revoke` |
| Data scope: admin lists of users, login histories, online sessions and audit logs, role member lists and counts, and the dashboard's user/login/session/audit figures only cover users inside the caller's session data scope (asset statistics stay global: the asset library is shared) (active roles, union, "ALL" wins, self always included); single-record operations on users outside it answer 404. Assigning a role or setting a role's data scope may not widen anyone beyond the caller's own scope; new roles start as `SELF` | `RBACService.SessionScope` / `EnsureUserVisible` / `EnsureCanAssignRole` / `EnsureCanSetRoleDataScope`, `query.UserScope`, `handler/scope.go` |
| Every password a person sets passes the password policy (length in characters, ≤72 bytes, optional complexity); the expired-password change shares the password login's attempt limit and captcha | `PasswordPolicy.Validate` in `service/setting_helper.go`, `LoginService.ChangeExpiredPassword` |
| Token refresh invalidates the old token; logout adds it to the blacklist | `middleware/auth.go`, `service/token.go` |
| Verification codes limit failed attempts, are single-use, and use constant-time comparison | `service/verification_code.go`, `external/verification_code.go` |
| Non-development mode rejects placeholder secrets; `init-db` requires an admin password | `infrastructure/config/load.go`, `service/user.go` |
| Multiple deployments may share PostgreSQL / Redis / S3: each owns its database (and role), bucket (and user), and Redis key prefix `General.InstanceID`; all Redis keys are built via `rediskey.Namespace.Key` | `pkg/rediskey`, `TestRedisKeysNamespaced` in `architecture_test.go`, `scripts/compose-instance.py` |
| On startup the API claims the Redis namespace with the deployment ID stored in the database, and refuses to start if another deployment already holds it | `cache.ClaimNamespace`, `database.DeploymentID` |
| The JWT `aud` is the `InstanceID`; tokens issued by other instances cannot access or refresh (even if the same `JwtKey` is misused); each deployment's `JwtKey` and RSA keys must still be distinct | `identityFromClaims` in `middleware/auth.go` |
| Sensitive data (passwords, verification codes, tokens) never goes into logs or audit details | Global |
| Frontend login state lives only in the httpOnly `jwt` cookie; the browser never reads the token | `apps/web/src/lib/api-client.ts` |
| The `jwt`/`csrf_token` cookies live for the refresh window ("remember me") or the browser session, never just the access-token lifetime; a refreshed token is always a new token and the old one is blacklisted, including refreshes done by `proxy.ts` | `authCookieMaxAge` in `middleware/auth.go`, `refreshSession` in `apps/web/src/proxy.ts` |
| The `redirect` parameter must go through `safeRedirectPath` | `apps/web/src/lib/safe-redirect.ts` |
| Adding a new external resource origin requires updating the CSP | `apps/web/src/lib/security-headers.ts` |
| Exports reuse the list's filter/sort validation and data scope, stop at 10,000 rows (`ErrExportTooLarge`) instead of truncating, and are audited; CSV cells starting with `= + - @` tab or CR get a `'` prefix (formula injection) and xlsx cells are always strings | `handler/export.go`, `pkg/tabular` |
| Imports cap the file (5 MB, 1,000 rows, 50 MB unzipped for xlsx), accept only `.xlsx` / UTF-8 `.csv`, validate every row before creating anything, and apply the same rules as manual creation (data scope, contact uniqueness, password policy); imported users share an initial password that is already expired, so each must change it at first sign-in | `handler/user_io.go`, `service/user_import.go` |
| Frontend permission checks only control visibility; backend RBAC is the sole security boundary | — |

## 7. Frontend–backend contract

- **Paths**: API prefix `/api/v1`; the browser accesses it same-origin via a Next.js rewrite; server components connect directly via `CASTOR_API_URL`.
- **Responses**: `{ code, data, message }`; `code === 200` means success; `message` is already localized per `Accept-Language` and can be shown by the frontend as is. Error responses also carry `errorCode`, the business code from `response/errors.go` (e.g. `2002` captcha required, `2009` password expired); the frontend branches on it (`CastorApiError.errorCode`, `CastorErrorCode`), never on `code`, which is only the HTTP status.
- **Pagination**: request `page`, `pageSize` (default 10, max 500); response `data: { total, list, page, pageSize, totalPages }`.
- **Filtering/sorting**: `{field}-{op}=value` (op: `like|eq|ne|gt|gte|lt|lte|in`), `searchText` + `searchFields`, `order=field asc|desc` (at most 3 items); invalid values return 400.
- **Authentication**: before login, fetch the RSA public key to encrypt the password; the login body may set `rememberMe`; the backend sets the httpOnly `jwt` cookie and the `csrf_token` cookie (persistent for `JwtMaxRefreshHours` with "remember me", otherwise session cookies); write requests carry the `X-CSRF-Token` header; on 401 the frontend refreshes once and retries, and `proxy.ts` does the same for page requests. A password login answered with `errorCode` 2009 lets the user replace the expired password via `PUT /api/v1/auth/password/expired` (current + new password, RSA-encrypted). A login of a two-factor account is answered with `errorCode` 2012 and `data: { challenge, expiresIn }`; `POST /api/v1/auth/login/totp { challenge, code }` (authenticator or recovery code) then returns the normal login response (2013 wrong code, 2014 challenge expired). OIDC sign-in is a browser navigation to `/api/v1/auth/oidc/{provider}/authorize?redirect=&remember=`; the callback sets the cookies and redirects, or redirects to `/auth/sign-in?oidcError=…` / `?mfaChallenge=…`; the provider's redirect URI is `{General.PublicURL}/api/v1/auth/oidc/{provider}/callback`.
- **Permission identifiers**: `"{resourcePath}:{METHOD}"`, e.g. `/api/v1/admin/users/:id:PUT`, from `/api/v1/account/permissions`.
- **Dictionaries**: `/api/v1/account/dictionaries` (login required) returns `{ [typeCode]: DictItem[] }`, containing the enabled dictionary items of all enabled types; the admin layout prefetches it on the server, and the frontend reads it via `useDict()` / `<DictBadge>`. Unauthenticated `/api/v1/dictionaries` contains only public types. A dictionary item's `color` is a `tag-*` token name; `icon` is a key of `Icons`.
- **Export / import**: `GET /api/v1/admin/{users,audit-logs,login-histories}/export` takes the list's own filter/search/sort parameters plus `format=xlsx|csv` and `tz` (IANA zone for times; defaults to the API's zone), and answers with an attachment or the usual error envelope. `GET /api/v1/admin/users/import-template?format=` returns headers like `Username* (username)`; `POST /api/v1/admin/users/import` is multipart (`file`, RSA-encrypted `password`). A rejected import answers 400 `ErrImportInvalidRows` with `data: { created, errors: [{ line, field, code, message }] }` (`message` localized). Headers and dictionary-backed cells are localized per `Accept-Language`.
- **Files**: file fields in business records are asset `objectKey`s (including `users.avatar`); the display URL is generated by frontend `assetUrl(objectKey)`: unauthenticated `/api/v1/assets/download/:objectKey` (public assets only) or admin `/api/v1/admin/assets/download/:objectKey`. Private attachments are downloaded through the business module's own routes; for request/response fields see "Files in business modules" in the api AGENTS.md.
- **Notifications**: `GET /api/v1/account/notifications/stream` is a Server-Sent Events stream (same-origin `EventSource`, cookie auth): `unread` `{count}` on connect and after every change, `notification` `{id, title, type, level, link}` for new ones; clients reconnect after refreshing the token. Admin notifications may set `sendEmail` only when `GET /api/v1/admin/notifications/channels` reports `email`; users opt out with `PUT /api/v1/account/notification-preferences { muteNotificationEmails }`.
- **OpenAPI**: `apps/api/openapi.json` (OpenAPI 3.1) is generated from the route catalog and Go types, committed, and served to authorized admins at `GET /api/v1/admin/openapi.json`; the dashboard's "API Docs" page renders it. Generated clients or contract tests should read that file.
- **Navigation**: `/api/v1/account/navigation` returns the menu tree and `routes[{path, allowed}]`; frontend `src/proxy.ts` uses it to guard `/dashboard/*`; `/` is the public home page and does not call this endpoint.
- **Public settings**: `site.name`, `site.description`, and `feature.register.enabled` in `/api/v1/settings/public` determine the public site's branding and registration entry.
- **Error codes**: `0` success, `1xxx` general, `2xxx` authentication/authorization, `3xxx` users, `4xxx` assets, `5xxx` configuration, `9xxx` internal errors (defined in `apps/api/internal/interfaces/api/response/errors.go`).

## 8. Commit conventions

Format: `<type>(<scope>): <description>`; the description may be in Chinese. Allowed types:

`feat` new feature · `fix` bug fix · `perf` performance · `refactor` refactoring · `style` formatting without logic changes · `test` tests · `docs` documentation · `chore` dependencies/scaffolding · `ci` continuous integration · `types` type definitions · `revert` revert

Git hooks (enabled after `bun install`): pre-commit formats staged files and checks gofmt; pre-push builds the frontend when it has changes, and runs vet/test on changed Go packages.
